## 1. Project Purpose & Problem Space

GrainGuardian is an offline-first agricultural IoT and mobile decision-support system designed specifically for smallholder paddy (*Oryza sativa* L.) farmers in Andhra Pradesh and rural India. 

### The Core Agricultural Hazard
Traditional post-harvest paddy management relies on subjective sensory heuristics (teeth-biting, fingernail indentation, feeling bags by hand), leading to severe post-harvest losses:
1. **Premature Bagging ($>14.0\%$ Moisture):** Triggers internal hot-spot development, high respiration, and rapid colonization by *Aspergillus flavus*, causing carcinogenic **Aflatoxin B1 contamination** within 48–72 hours.
2. **Excessive Sun-Drying ($<12.0\%$ Moisture):** Over-drying causes microscopic fissures in the grain endosperm, leading to **25–30% grain breakage** during commercial rice milling (*Head Rice Yield* collapse).
3. **Internal Storage Hotspots:** Due to low thermal conductivity of bulk grain ($k \approx 0.12 - 0.15\text{ W/m}\cdot\text{K}$), heat generated by insect pests or microbial activity remains trapped in the core of 50–75 kg grain piles, causing complete loss of germination viability without showing external signs.

### The Engineered Solution
GrainGuardian pairs a physical 1-meter multi-depth probe (SEN0193 capacitive moisture probe + 3x Maxim DS18B20 digital temperature sensors + DHT11 environmental sensor) via Bluetooth Low Energy (BLE GATT) with a native Android application. It provides:
- **Mode A (Spot Drying Check):** Verifies moisture equilibrium against Bureau of Indian Standards (BIS) safe limit ($13.5\%$) to advise whether grain is ready for bagging or requires additional drying.
- **Mode B (Storage Health Monitoring):** Detects internal heat accumulation across three depths ($10\text{ cm}$, $40\text{ cm}$, $80\text{ cm}$) using a deterministic Thermal Gradient Index ($\text{TGI} = \max(T) - \min(T)$) to alert farmers to deep hotspot development.
- **100% Offline-First Edge Execution:** Operates with zero dependency on active internet, cellular networks, cloud servers, or third-party APIs.

## 3. Actual Architecture vs. Slide Deck Claims

A critical finding of this audit is the distinction between early conceptual proposals and the actual implemented system:

- **Original PPT / Proposal Architecture (Conceptual):**
  Proposed an Internet-of-Things cloud pipeline involving ESP32 Wi-Fi upload $\rightarrow$ FastAPI Python backend $\rightarrow$ Supabase cloud PostgreSQL $\rightarrow$ React web dashboard.
- **Actual Implemented Repository Architecture (Edge V1):**
  Physical sensors $\rightarrow$ ESP32 DevKit V1 $\rightarrow$ BLE GATT Server (ASCII stream) $\rightarrow$ Android Native Client (`BleManager.kt`) $\rightarrow$ Unidirectional Data Flow (`GrainViewModel.kt`) $\rightarrow$ Deterministic Agronomic Decision Engine (`GrainDecisionEngine.kt`) $\rightarrow$ Local Room SQLite Database (`inspections` table) $\rightarrow$ Jetpack Compose bilingual UI.

**Auditor Evaluation:** The transition to an offline-first BLE architecture is technically defensible and superior for rural agricultural contexts where cellular 4G/5G data is unavailable in drying yards (*kallalu*) and remote storage godowns.
